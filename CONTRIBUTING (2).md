# Contributing to CeloHT

Thank you for considering a contribution to CeloHT. This guide covers the organization-wide basics; individual repositories may add their own specific instructions on top of this.

## Ways to Contribute

You don't need to write code to contribute meaningfully:

| Contribution | Where |
|---|---|
| Fix a typo, clarify a sentence | Any repository — small doc PRs are always welcome |
| Report a bug | [Open an issue](https://github.com/Celo-HT/CeloHT/issues/new/choose) using the Bug Report template |
| Suggest a feature | Open an issue using the Feature Request template |
| Improve documentation | See the specific repository's `CONTRIBUTING.md` for its documentation standards |
| Contribute research | See [celoht-research](https://github.com/Celo-HT/celoht-research)'s `CONTRIBUTING.md` |
| Translate content | See the main documentation repository's `TRANSLATION_GUIDE.md` |
| Answer questions | Join [Discussions](https://github.com/orgs/Celo-HT/discussions) |
| Write code | Follow the relevant repository's developer guide |

## Before You Start

1. **Read the Code of Conduct.** See [CODE_OF_CONDUCT.md](./CODE_OF_CONDUCT.md) — it applies everywhere in this organization.
2. **Search first.** Check existing issues and discussions before opening a new one, to avoid duplicated effort.
3. **Understand what CeloHT is (and isn't).** CeloHT has no token, no ICO, and is not an investment platform — see the main documentation repository's `NO_TOKEN_POLICY.md`. Contributions should never introduce language implying otherwise.

## Contribution Workflow

```
1. Find or open an issue describing the change
2. Fork the repository (or branch, if you're a maintainer)
3. Make your change, following the repository's specific standards
4. Open a pull request referencing the issue
5. Respond to review feedback
6. Get merged — and see yourself credited in the repository's AUTHORS.md
```

## Repository-Specific Guides

Each repository has its own detailed contributing guide with specifics relevant to that repository:

- [CeloHT (docs)](https://github.com/Celo-HT/CeloHT/blob/main/CONTRIBUTING.md) — governance, technical, and program documentation
- [celoht-research](https://github.com/Celo-HT/celoht-research/blob/main/CONTRIBUTING.md) — research contributions and peer review
- [Brand](https://github.com/Celo-HT/Brand/blob/main/CONTRIBUTING.md) — brand asset and guideline contributions

This organization-wide guide applies as a baseline everywhere; a repository's own `CONTRIBUTING.md`, where present, adds detail specific to that repository and takes precedence on anything more specific.

## Quality Standard

Every CeloHT repository holds contributions to the same basic standard: **complete, not placeholder**. A pull request that says "documentation TODO" or leaves a section unfinished won't be merged as-is — see the specific repository's contribution guide for what "complete" means in that context.

## Good First Contributions

Look for issues tagged `good-first-issue` across CeloHT repositories. If nothing fits, open a documentation-improvement PR — a well-written, small doc fix is a completely legitimate first contribution.

## Recognition

Contributors are credited in each repository's `AUTHORS.md` as their work is merged.

## Questions

Open a [Discussion](https://github.com/orgs/Celo-HT/discussions) or see [SUPPORT.md](./SUPPORT.md).
